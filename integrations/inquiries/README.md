# 무료상담·기관협력 접수 운영

## 현재 구성

- 프론트엔드: `/consultation/`, `/partnership/`; 전화·이메일 대체 문의 유지.
- Apps Script: 이 디렉터리의 `Code.gs`. 공개 제출용 URL은 `src/config/inquiries.mjs`에서 관리.
- 저장: 운영자가 지정한 `한지붕_비영리` Google 스프레드시트의 `상담문의`, `기관협력` 탭.
- 2026-09-24, 운영자 승인 후 버전 1 웹 앱 배포. 배포 계정으로 실행하며 방문자는 로그인 없이 제출. 스프레드시트 일반 접근은 제한됨, 기존 개별 권한은 유지.
- Apps Script 배포와 GitHub Pages 프론트엔드 배포는 별개입니다.

공개 API는 문의 목록이나 연락처를 반환하지 않습니다. `GET`은 서비스 상태, `POST submit`은 저장, `POST status`는 접수 종류와 무작위 접수번호로 저장 사실만 확인합니다. API 응답에는 접수번호·종류·시각만 포함됩니다.

## 운영자가 해야 할 일

1. 두 탭을 정기적으로 확인하고 선택한 연락방법으로 답변합니다. 현재 자동 이메일 알림과 처리 기한 보장 기능은 없습니다.
2. K열 처리상태를 관리하고 상담 종료 시 L열에 실제 종료일, M열에 삭제 예정일을 기록합니다.
3. 개인정보는 상담 종료일부터 최대 1년 보관 후 삭제합니다. 현재 자동 파기 기능은 없으므로 담당자가 정기 점검해야 합니다. 법령상 보관 의무가 있으면 별도 근거·범위를 관리합니다.
4. 지정된 운영담당자만 편집 권한을 가지도록 개별 공유자도 점검합니다. 링크 공개·웹 게시·공개 사본 생성은 하지 않습니다.
5. 주민등록번호·상세주소·계약서 등 불필요한 민감정보가 들어오면 담당자가 확인하고 불필요한 내용을 삭제합니다. 문자열 검증만으로 모든 민감정보가 차단되지는 않습니다.

## 실패와 중복 처리

브라우저는 저장 후 서버가 접수번호를 확인해야 성공으로 표시합니다. 응답 지연·네트워크 실패 시 입력을 유지하며 성공 화면으로 보내지 않습니다. 같은 내용을 그대로 다시 보내면 같은 접수번호를 사용해 중복 저장을 방지합니다. 입력을 수정하면 새 문의로 취급합니다.

직접 완료 URL에 방문한 것만으로 접수 완료가 되지 않습니다. 브라우저에는 연락처나 문의내용을 저장하지 않고 해당 탭의 `sessionStorage`에 접수번호·종류·시각만 저장합니다. 완료 화면에서도 서버에 저장 여부를 재확인합니다.

## 보안·한계

- 서버 검증, 허용된 두 탭만 쓰기, 길이 제한, 동의 버전 확인, 수식 삽입 방지, 잠금과 중복 방지 적용.
- 기본 허니팟 및 일일 신규 100건 전체 상한. 사람별 제한, CAPTCHA, WAF 또는 DDoS 방어를 제공한다는 뜻은 아닙니다. 악의적 요청이 상한·Google 할당량을 소진할 수 있어 운영 중 감시가 필요합니다.
- 자동 알림·자동 파기·첨부파일·문의목록 조회·Ads/GA4 측정은 미구현입니다.
- Workspace 계약, Google 처리 지역·위탁/국외이전 고지 적용 여부는 실제 조직 계약과 운영에 맞춰 확인해야 합니다.
- 접수 성공 시험 3행은 `시스템 시험(상담 집계 제외)`로 표시했습니다. 실제 상담 실적으로 집계하지 않습니다.

## 수정·재배포

1. `Code.gs`와 동의 버전·문의 유형 설정을 함께 검토하고 `npm run check` 실행.
2. 해당 시트에 연결된 기존 Apps Script 프로젝트에서 새 버전을 저장한 뒤 기존 배포를 갱신합니다. 대상 시트·실행 계정·접근 범위를 확인하고 다른 프로젝트는 건드리지 않습니다.
3. 엔드포인트가 바뀌면 `src/config/inquiries.mjs`를 수정하고 프론트엔드도 별도 빌드·배포합니다.
4. 명확한 시험 문의로 양쪽 탭 저장, 중복 방지, 실패 표시, 접수번호 재확인을 검증합니다. 시험 내용에 실제 회원 개인정보를 넣지 않습니다.

## 원복

- 프론트엔드 문제가 생기면 해당 배포 커밋을 `git revert <commit>`로 되돌리고 검사 후 재배포합니다. 강제 푸시나 기존 운영 배포 삭제는 필요 없습니다.
- 접수를 일시 중지하려면 endpoint를 빈 문자열로 변경하여 폼을 비활성화하고 전화·이메일 대안을 유지한 채 재배포합니다. 이미 공개된 API도 중지해야 한다면 Apps Script의 해당 새 배포를 보관 처리합니다. 기존 접수 데이터는 삭제하지 않습니다.
- 백엔드 변경은 배포 관리에서 직전 검증된 버전으로 되돌립니다.
- 스프레드시트 제한됨 설정은 개인정보 보호를 위해 유지합니다. 되돌릴 필요가 생기면 소유자가 공유 범위를 명시적으로 결정해야 하며 조직 전체 링크 공유를 자동 복구하지 않습니다.
- DNS·도메인·기존 호스팅은 이 작업에서 변경하지 않았습니다.
